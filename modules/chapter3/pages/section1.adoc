= Initializing Sites
:navtitle: Initializing Sites

== Overview

A Service Interconnect site is the foundation of the application network.
Before you can link sites, expose services, or route traffic, you must create a site in each namespace or location that will participate in the network.

In the previous chapter, you created sites as part of the installation exercise.
This section covers site creation in more detail, including important options and the YAML alternative.

[NOTE]
====
Before creating a site, the Skupper controller and Custom Resource Definitions (CRDs) must be installed on the target Kubernetes cluster.
If you have not yet installed the controller, refer to xref:chapter2:section1.adoc[Installing Service Interconnect] for instructions.
====

== Creating a Site with the CLI

The basic command to create a site is:

[source,bash]
----
skupper site create <site-name> --namespace <namespace>
----

Specifying the namespace is not required if your current context is already set to the target namespace.

[source,bash,role=execute]
----
oc project site-west
skupper site create site-west
----

.Expected output
----
Waiting for status...
Site "site-west" is ready.
----

You can check the status of the site at any time:

[source,bash,role=execute]
----
skupper site status
----

== Enabling Link Access

By default, a site does not accept incoming links from other sites.
To allow other sites to link to this site, enable link access:

[source,bash,role=execute]
----
skupper site create site-west --enable-link-access
----

You can also enable link access on an existing site:

[source,bash,role=execute]
----
skupper site update --enable-link-access
----

When link access is enabled, the site deploys a grant server that can issue access tokens for remote sites.

== Creating a Site via the OpenShift Console

You can create a site through the Installed Operators interface in the OpenShift web console.

. Navigate to *Ecosystem -> Installed Operators*.
. Select the *Red Hat Service Interconnect Operator*.
. Click the *Site* tab.
. Click *Create Site*.
. Switch to the *YAML view* to review and edit the Site resource:
+
* Set the `metadata.name` to the desired site name (e.g., `site-west`)
* Set `spec.linkAccess` to `default` if other sites need to link to this site
+
Leave other fields at their defaults unless you need to customize them.

. Click *Create*.
. The site details page shows the site status. Wait until the status shows *Ready*.

== Creating a Site with YAML

You can also create a site by applying a `Site` custom resource:

[source,yaml]
----
apiVersion: skupper.io/v2alpha1
kind: Site
metadata:
  name: site-west
  namespace: site-west
spec:
  linkAccess: default
----

Apply the resource:

[source,bash,role=execute]
----
oc apply -f site-west.yaml
----

Check the status:

[source,bash,role=execute]
----
oc get site
----

.Expected output (site may be pending briefly)
----
NAME        STATUS   SITES IN NETWORK   MESSAGE
site-west   Ready    1                  OK
----

== Deploying the Network Observer Console

Now that you have a site, you can deploy the Network Observer to get a web-based console for visualizing your application network.
The Network Observer operator should already be installed from xref:chapter2:section3.adoc[the previous chapter].

Create a `NetworkObserver` custom resource in the same namespace as your site:

[source,yaml]
----
apiVersion: observability.skupper.io/v2alpha1
kind: NetworkObserver
metadata:
  name: network-observer
  namespace: site-west
spec: {}
----

[source,bash,role=execute]
----
oc apply -f network-observer.yaml
----

After the deployment is ready, find the console route:

[source,bash,role=execute]
----
oc get route -n site-west | grep network-observer
----

Open the route URL in a browser.
On OpenShift, you can log in using your OpenShift credentials.

As you build out your application network, look for *Console Checkpoint* callouts throughout the course -- they tell you when to check the console and what has changed.

[TIP]
.Console Checkpoint
====
Open the Network Observer console URL in your browser.
In the *Topology* view, you should see a single site node (`site-west`).
There are no links or services yet -- that will change as you progress through the next sections.
====

The console shows the same information you can get from the CLI, but as a live visual:

[cols="1,1",options="header"]
|===
|CLI Command |Console View

|`skupper site status` / `oc get site`
|Topology view (site nodes)

|`skupper link status`
|Topology view (link edges)

|`skupper connector status` / `skupper listener status`
|Services view

|`curl` / traffic tests
|Traffic flow (throughput on links and services)
|===

NOTE: For detailed configuration options including resource tuning and authentication strategies, see xref:chapter6:section3.adoc[Network Observer and the Console].

== Site Options

There are many options to consider when creating sites:

[cols="1,2",options="header"]
|===
|Option |Description

|`--enable-link-access`
|Allow other sites to create links to this site (CLI). Equivalent to `spec.linkAccess: default` in YAML.

|`--timeout <time>`
|Maximum time for the CLI to wait for the site to report ready (e.g., `2m`).
The timeout does not prevent the site from being created.

|`--enable-ha`
|Enable high availability for the site. Runs multiple router replicas so the site remains operational if a router instance fails.

|`--namespace <namespace>`
|Create the site in a specific namespace (CLI).
|===

=== Site Sizing

By default, the Skupper router runs with BestEffort CPU allocation.
For production or high-throughput deployments, you can configure the router's CPU allocation using the `spec.settings.size` field in the Site resource or by creating a ConfigMap with the `skupper.io/site-sizing` label.

Available sizing options:

[cols="1,1,2",options="header"]
|===
|Size |CPU Allocation |Use Case

|_(default)_
|BestEffort
|Development and testing

|`small`
|1 CPU
|Low-resource clusters or edge sites

|`medium`
|2 CPU
|Production workloads

|`large`
|5 CPU
|High-throughput or latency-sensitive deployments
|===

.Example: Setting site size in YAML
[source,yaml]
----
apiVersion: skupper.io/v2alpha1
kind: Site
metadata:
  name: site-west
spec:
  settings:
    size: medium
----

== Deleting a Site

To remove a site using the CLI:

[source,bash,role=execute]
----
skupper site delete
----

Or delete the Site resource directly:

[source,bash,role=execute]
----
oc delete site site-west
----
