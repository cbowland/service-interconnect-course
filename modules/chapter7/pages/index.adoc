= Advanced Scenarios
:navtitle: Advanced Scenarios

== Overview

The previous chapters covered the core mechanics of Red Hat Service Interconnect: creating sites, linking them, and exposing services across boundaries.
This chapter applies those building blocks to real-world architectural patterns that organizations encounter when operating distributed applications.

Service Interconnect is designed for environments where applications span multiple clouds, data centers, and edge locations.
Because it operates at Layer 7 and requires no changes to the underlying network infrastructure, it is well-suited for scenarios where traditional networking approaches (VPNs, direct peering, dedicated circuits) are too complex, too expensive, or simply not possible.

This chapter explores three categories of advanced patterns:

* **Multi-cloud connectivity** — Connecting services that run across different cloud providers and on-premises environments
* **Progressive migration** — Incrementally moving workloads from one environment to another without downtime
* **Edge computing** — Extending the application network to distributed edge locations

== Objectives

On completing this chapter, you should be able to:

* Design a Service Interconnect topology for multi-cloud and hybrid environments
* Plan a progressive migration strategy using parallel service deployment and traffic shifting
* Apply link cost to control traffic routing between preferred and failover sites
* Identify the considerations for deploying Service Interconnect at the edge
* Implement a simulated multi-cloud migration scenario using your lab environment
