Initializing Sites

Overview

A Service Interconnect site is the foundation of the application network. Before you can link sites, expose services, or route traffic, you must create a site in each namespace or location that will participate in the network.

In the previous chapter, you created sites as part of the installation exercise. This section covers site creation in more detail, including important options and the YAML alternative.

Before creating a site, the Skupper controller and Custom Resource Definitions (CRDs) must be installed on the target Kubernetes cluster. If you have not yet installed the controller, refer to Installing Service Interconnect for instructions.

Creating a Site with the CLI

The basic command to create a site is:

skupper site create <site-name> --namespace <namespace>

Specifying the namespace is not required if your current context is already set to the target namespace.

oc project site-west
skupper site create site-west
Expected output
Waiting for status...
Site "site-west" is ready.

You can check the status of the site at any time:

skupper site status

Enabling Link Access

By default, a site does not accept incoming links from other sites. To allow other sites to link to this site, enable link access:

skupper site create site-west --enable-link-access

You can also enable link access on an existing site:

skupper site update --enable-link-access

When link access is enabled, the site deploys a grant server that can issue access tokens for remote sites.

Creating a Site via the OpenShift Console

You can create a site through the Installed Operators interface in the OpenShift web console.

  1. Navigate to Ecosystem → Installed Operators.

  2. Select the Red Hat Service Interconnect Operator.

  3. Click the Site tab.

  4. Click Create Site.

  5. Switch to the YAML view to review and edit the Site resource:

    • Set the metadata.name to the desired site name (e.g., site-west)

    • Set spec.linkAccess to default if other sites need to link to this site

      Leave other fields at their defaults unless you need to customize them.

  6. Click Create.

  7. The site details page shows the site status. Wait until the status shows Ready.

Creating a Site with YAML

You can also create a site by applying a Site custom resource:

apiVersion: skupper.io/v2alpha1
kind: Site
metadata:
  name: site-west
  namespace: site-west
spec:
  linkAccess: default

Apply the resource:

oc apply -f site-west.yaml

Check the status:

oc get site
Expected output (site may be pending briefly)
NAME        STATUS   SITES IN NETWORK   MESSAGE
site-west   Ready    1                  OK

Deploying the Network Observer Console

Now that you have a site, you can deploy the Network Observer to get a web-based console for visualizing your application network. The Network Observer operator should already be installed from the previous chapter.

Create a NetworkObserver custom resource in the same namespace as your site:

apiVersion: observability.skupper.io/v2alpha1
kind: NetworkObserver
metadata:
  name: network-observer
  namespace: site-west
spec: {}
oc apply -f network-observer.yaml

After the deployment is ready, find the console route:

oc get route -n site-west | grep network-observer

Open the route URL in a browser. On OpenShift, you can log in using your OpenShift credentials.

As you build out your application network in the following sections, the console will update in real time to show sites, links, and services.

For detailed configuration options including resource tuning and authentication strategies, see Network Observer and the Console.

Site Options

There are many options to consider when creating sites:

Option Description

--enable-link-access

Allow other sites to create links to this site (CLI). Equivalent to spec.linkAccess: default in YAML.

--timeout <time>

Maximum time for the CLI to wait for the site to report ready (e.g., 2m). The timeout does not prevent the site from being created.

--enable-ha

Enable high availability for the site. Runs multiple router replicas so the site remains operational if a router instance fails.

--namespace <namespace>

Create the site in a specific namespace (CLI).

Site Sizing

By default, the Skupper router runs with BestEffort CPU allocation. For production or high-throughput deployments, you can configure the router’s CPU allocation using the spec.settings.size field in the Site resource or by creating a ConfigMap with the skupper.io/site-sizing label.

Available sizing options:

Size CPU Allocation Use Case

(default)

BestEffort

Development and testing

small

1 CPU

Low-resource clusters or edge sites

medium

2 CPU

Production workloads

large

5 CPU

High-throughput or latency-sensitive deployments
Example: Setting site size in YAML
apiVersion: skupper.io/v2alpha1
kind: Site
metadata:
  name: site-west
spec:
  settings:
    size: medium

Deleting a Site

To remove a site using the CLI:

skupper site delete

Or delete the Site resource directly:

oc delete site site-west
