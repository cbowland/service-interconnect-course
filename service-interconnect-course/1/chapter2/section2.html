Installing the skupper CLI

Overview

The skupper CLI provides a command-line interface for creating and managing Service Interconnect resources. While you can manage everything through YAML and oc apply, the CLI simplifies common operations like creating sites, issuing tokens, and checking status.

The CLI is designed to generate and consume standard resources, ensuring that sites, links, and services configured using the CLI are identical to those configured directly through YAML.

For Kubernetes, you must install the CRDs and controller using YAML or the Operator before creating sites.

CLI Command Structure

The skupper CLI follows a consistent pattern:

skupper <resource-type> <operation> <resource-name> [options]

Resource types include site, token, listener, connector, and link. Operations include create, update, delete, status, and generate.

In Service Interconnect 2.1, CLI shortcuts (such as -r) have been removed. You must now specify the full parameter name, for example --routing-key.

Installing the CLI

There are two methods to install the CLI:

  • Downloading binaries from the Red Hat Software Downloads page

  • Using Red Hat packages on RHEL

Method 1: Download Binaries

  1. Download binary files for your system architecture from the Red Hat Software Downloads page. Choose the latest Version for 2.1.

  2. For a Mac with Apple silicon, use Rosetta 2 and the Skupper CLI for Mac on x86-64 download.

  3. Unzip the downloaded file and place the skupper executable on your PATH.

  4. Verify the installation:

    skupper version
    Expected output
    COMPONENT          VERSION
cli                2.1.3-rh-1

Method 2: Red Hat Packages (RHEL)

Installing Red Hat packages on Linux ensures you receive the latest updates to the Skupper CLI.

Prerequisites

  • Your system must be registered with a Red Hat subscription. See Registering the system and managing subscriptions for more information.

Red Hat Enterprise Linux 9

  1. Use the subscription-manager command to subscribe to the required package repository. Replace <version> with 2 for the main release stream:

    sudo subscription-manager repos \
  --enable=service-interconnect-_<version>_-for-rhel-9-x86_64-rpms

  2. Install the skupper-cli package:

    sudo dnf install skupper-cli

Red Hat Enterprise Linux 8

sudo subscription-manager repos \
  --enable=service-interconnect-_<version>_-for-rhel-8-x86_64-rpms
sudo dnf install skupper-cli
You can also install the skupper-router package, which is only necessary for Linux local system sites.

The SKUPPER_PLATFORM Environment Variable

The CLI behavior depends on the target platform, which is controlled by the SKUPPER_PLATFORM environment variable:

Value Behavior

kubernetes (default)

Commands target the current Kubernetes/OpenShift context

podman

Commands target local Podman containers

docker

Commands target local Docker containers

linux

Commands target local Linux system services

If SKUPPER_PLATFORM is unset, the CLI defaults to kubernetes.

When using a local system platform (podman, docker, or linux), you must first install the local controller by running skupper system install. This installs the Skupper controller as a container on the local system.

Local system site features (podman, docker, and linux platforms) are a Technology Preview in Red Hat Service Interconnect 2.1. Technology Preview features are not supported with Red Hat production service level agreements (SLAs) and might not be functionally complete.

 
export SKUPPER_PLATFORM=kubernetes

Verifying the CLI Installation

Run the following command to confirm the CLI is installed and display the version:

skupper version
Expected output
COMPONENT          VERSION
cli                2.1.3-rh-1

CLI Auto-completion

Enable shell auto-completion for faster command entry:

Bash

skupper completion bash > /etc/bash_completion.d/skupper
source /etc/bash_completion.d/skupper

Zsh

skupper completion zsh > "${fpath[1]}/_skupper"
source ~/.zshrc

Platform Behavior

The CLI behaves slightly differently depending on the platform:

Platform Behavior

Kubernetes / OpenShift

Commands block until the operation completes, an error occurs, or the timeout is exceeded. Use --wait and --timeout to control this behavior.

Docker / Podman / Linux

Commands place resources in the input location. Run skupper system reload to apply changes.

In this course, you will primarily use the CLI on Kubernetes/OpenShift, where commands block by default.
