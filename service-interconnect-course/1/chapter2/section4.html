Hands-on: Install and Verify

Lab Overview

In this exercise, you will install the Service Interconnect Operator, install the skupper CLI, and create your first sites. By the end of this exercise, you will have Service Interconnect ready to use in your lab environment.

Exercise Steps

Step 1: Install the Operator

If you have not already done so, install the Red Hat Service Interconnect Operator on your cluster(s) using the Software Catalog as described in the previous section.

Verify the operator is running:

oc get csv -n openshift-operators | grep skupper
Expected output
skupper-operator.v2.1.1-rh-3   Red Hat Service Interconnect   Succeeded

Confirm the CRDs are available:

oc get crd | grep skupper

Step 2: Install the Network Observer Operator

Install the Network Observer operator so you can use the web console later in the course.

oc apply -f - <<EOF
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: skupper-network-observer-operator
  namespace: openshift-operators
spec:
  channel: stable-2
  installPlanApproval: Automatic
  name: skupper-network-observer-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
EOF

Wait for the operator to install, then verify:

oc get csv -A | grep network-observer
Expected output
openshift-operators   skupper-network-observer-operator.v2.1.1-rh-8   ...   Succeeded
The operator alone does not deploy the console. You will create a NetworkObserver instance in the next chapter after your first site is ready.

Step 3: Install the CLI

Download and install the skupper CLI for your operating system as described in the previous section.

Verify the installation:

skupper version
Expected output
COMPONENT          VERSION
cli                2.1.3-rh-1

Confirm the platform is set to Kubernetes:

echo $SKUPPER_PLATFORM

If this returns a value other than kubernetes (or is empty, which defaults to kubernetes), set it:

export SKUPPER_PLATFORM=kubernetes

Step 4: Create the Namespaces

  • Option A: Two Clusters

  • Option B: Single Cluster

On Cluster A:

oc login --server=<cluster-a-api-url> -u <username> -p <password>
oc new-project site-west

On Cluster B:

oc login --server=<cluster-b-api-url> -u <username> -p <password>
oc new-project site-east
oc login --server=<cluster-api-url> -u <username> -p <password>
oc new-project site-west
oc new-project site-east

Step 5: Create the Sites

Create a site in the site-west namespace with link access enabled (this site will accept incoming links):

oc project site-west
skupper site create site-west --enable-link-access

The CLI will block until the site is ready:

Expected output
Waiting for status...
Site "site-west" is ready.

Verify the site status:

skupper site status
Expected output
NAME        STATUS
site-west   Ready

Create a site in the site-east namespace:

  • Option A: Two Clusters

  • Option B: Single Cluster

Switch to Cluster B:

oc login --server=<cluster-b-api-url> -u <username> -p <password>
oc project site-east
skupper site create site-east
oc project site-east
skupper site create site-east

Verify the site status:

skupper site status
Expected output
NAME        STATUS
site-east   Ready

Step 6: Verify Both Sites

Confirm that both sites are running by checking the site pods in each namespace:

oc get pods -n site-west | grep skupper
oc get pods -n site-east | grep skupper

You should see the Service Interconnect router pods running in each namespace.

Summary

In this exercise, you:

  • Installed the Red Hat Service Interconnect Operator on your OpenShift cluster(s)

  • Installed the Red Hat Service Interconnect Network Observer Operator

  • Installed the skupper CLI and verified the version

  • Confirmed the SKUPPER_PLATFORM environment variable

  • Created two namespaces (site-west and site-east)

  • Initialized a Service Interconnect site in each namespace with skupper site create

  • Verified that both sites are running and ready

In the next chapter, you will link these sites together and expose services across the application network.
