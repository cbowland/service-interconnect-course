What is Red Hat Service Interconnect?

Overview

Red Hat Service Interconnect is a multi-site, multi-platform application connectivity solution that enables services running in different environments to communicate securely — without requiring VPNs, special firewall rules, or elevated network privileges.

Service Interconnect is a Red Hat build of the open-source Skupper project. It is available through a Red Hat software subscription.

The Problem

Modern applications are increasingly distributed across multiple environments:

  • Multiple OpenShift or Kubernetes clusters in different regions

  • A mix of on-premises data centers and public cloud providers

  • Legacy applications running on virtual machines or bare-metal servers

  • Edge locations with limited or intermittent connectivity

Connecting services across these boundaries traditionally requires significant network infrastructure work: VPN tunnels, firewall rule changes, network peering agreements, and coordination between network and platform teams. These approaches are complex, slow to provision, and often require elevated privileges that application teams do not have.

The Solution

Service Interconnect creates an application network — a Layer 7 overlay that routes traffic between application endpoints across distributed sites. Rather than modifying the underlying network infrastructure, Service Interconnect deploys lightweight routers that establish secure, outbound-only connections between sites.

Key characteristics of this approach:

  • Layer 7 routing — Service Interconnect operates at the application layer, routing messages between service endpoints rather than forwarding IP packets. Application services appear local to consumers, regardless of where they actually run.

  • No infrastructure changes — Sites connect using standard outbound HTTPS connections. No VPN tunnels, firewall ingress rules, or network peering is required.

  • Mutual TLS by default — All router-to-router connections are encrypted using a private, dedicated certificate authority (CA). Each router is uniquely identified by its own certificate.

  • Namespace-level operation — Each Service Interconnect site operates within a Kubernetes namespace (or on a Linux host), requiring no cluster-wide privileges to set up.

Platform Support

Service Interconnect 2.1 supports the following platforms:

Kubernetes Sites

  • Red Hat OpenShift Container Platform — All versions in Full or Maintenance support

  • Non-OpenShift Kubernetes — Any CNCF-certified distribution, version 1.28 or later

Red Hat provides assistance running Service Interconnect on any CNCF-certified distribution of Kubernetes, though primary testing is done on OpenShift.

The operator is supported with OpenShift 4.x only. On non-OpenShift Kubernetes, use YAML or the CLI to install the CRDs and controller.

Supported Ingress Types

  • LoadBalancer and OpenShift Routes (supported on OpenShift)

  • Gateway, Contour, Nginx (requires TLS passthrough configuration), and NodePort are also supported

Local System Sites (Podman, Docker, Linux)

  • Red Hat Enterprise Linux 8 — Podman sites on x86-64, aarch64, s390x, ppc64le

  • Red Hat Enterprise Linux 9 — Podman sites on x86-64, aarch64, s390x, ppc64le

  • Podman version 4 or later is required
